Packaging correction:
  The first candidate accidentally reused an old padded-Image-plus-appended-DTB
  pattern and was about 963 KiB larger than verified s5fy. It was rejected
  before flashing. The final image uses raw Image plus a separate boot-header
  DTB and matches the verified s5fy layout and size.

Boot verification:

Audible test 1:
  Both PA mixer volumes were temporarily set to 360 / 0 dB.
  1 kHz, stereo, 48 kHz, 6 seconds; speaker-test exit 0.
  Both AW88261 devices reported PLL 0x0011, SYSST 0x0311 and start success.
  The user immediately confirmed: "ok响了".
  Both PA volumes were restored to the default 270 / -22.5 dB.

Repeated IV sampling during 1 kHz at default volume:
  0-0034: ISNDAT -20…47, VSNDAT -28…69
  0-0035: ISNDAT -12…12, VSNDAT 0…0
  This is the first real voltage/current response and directly distinguishes
  SD1 from the silent SD0 result. PA 0x34 is producing output; PA 0x35 is not
  proven active.

Logical channel test:
  Both PA mixer volumes were temporarily set to 330 / -7.5 dB.
  700 Hz logical left only, pause 1 second, then 1200 Hz logical right only.
  Both commands completed and the user confirmed: "都在响".
  Both PA volumes were restored to 270 / -22.5 dB.

Physical-PA isolation test:
  Segment A: PA mixer numid 1 / 0x34 = 330, numid 3 / 0x35 = 0;
             stereo 800 Hz for one speaker-test iteration.
  Pause:     2 seconds.
  Segment B: PA mixer numid 1 / 0x34 = 0, numid 3 / 0x35 = 330;
             stereo 1400 Hz for one speaker-test iteration.
  Both segments completed and both mixer values were restored to 270.
  The user confirmed: "有声音。两断都响。" Therefore both 0x34 and 0x35
  physical amplifier paths are audible. The earlier zero VSNDAT reading from
  0x35 is a feedback telemetry anomaly and must not be used to label it silent.

  The first host invocation accidentally used the unsupported option
  --timeout; argparse rejected it before opening ACM, so nothing reached the
  phone. It was corrected to --command-timeout. In this tool sandbox the
  existing ttyACM0/2 nodes were hidden even though sysfs showed both devices
  active and bound to cdc_acm; the authorized exact ports were then used to
  short-tap power via the servo and run the test.

Conclusion:
  PASS_PHYSICAL_AUDIBLE and PASS_DUAL_PA_AUDIBLE. The s5fy silence was caused by topology selecting SD0.
  Working speaker playback is on SD1, corresponding to the stock gpio128/data1
  pin. Both logical channels and both isolated physical PA paths are audible.
